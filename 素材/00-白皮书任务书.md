# 白皮书任务书(写给撰写工人)

## 你要产出的东西
一份《Orca 编排实战白皮书》,放在 `白皮书/` 目录,文件名 `orca-orchestration.md`。目标读者:会动手但没接触过 Orca 编排的人(homelab 玩家、独立开发者)。读者读完应该能**不看任何外部资料,独立完成一次完整的编排测试**(这将是本仓库的验收标准,见 `验收/` 目录的验收指令)。

## 结构要求(章节)
1. **这是什么**:一句话定位 + 解决什么问题(把"派 agent 干活、自动回执、结果入库"从手工拼装变成一条命令)
2. **核心概念**(配 mermaid 图,高中生可读,每个名词跟一句大白话):Run(账本)、Coordinator(协调者)、Worker(工人)、Task(任务)、Dispatch(工单)、worker_done(完工回执)、heartbeat(心跳)
3. **七步标准流程**:status → run-create → worker-start → (心跳) → check --wait 收回执 → 证据验收 → ack + release。每步:命令原文 + 干什么 + 怎么确认成功
4. **隔离通道(两步法)**:为什么 folder 项目不能直接 `--worktree new-child`,正确姿势 = 先 `worktree create` 再 `worker-start --worktree id:完整id`
5. **验收纪律**:回执 ≠ 完成;三件套证据(回执内容 / git 提交与 diff / worker-show 状态);启动类命令必须验证世界状态
6. **踩坑实录**:按 `素材/03-踩坑案例.md` 改写成教学案例(每个坑:错误做法/为什么错/正确做法)
7. **安全带:skill 门禁**:为什么需要 + 设计原理(读全文才登记,动作命令无登记即拦)——引用 `素材/04-门禁设计.md`
8. **附录**:完整命令速查表(一张表)

## 写作纪律
- 所有命令必须是本仓库 `素材/01-命令序列.md` 里验证过的原文,**禁止编造参数**(本仓库的历史就是被编造参数毁掉过一次,见踩坑实录)
- 术语第一次出现必须带大白话解释
- mermaid 图:每张图前一句"这张图讲什么",图后逐节点注释
- 中文;提交信息:`docs: Orca 编排实战白皮书首版`
- 只写 `白皮书/` 目录,不碰其他文件
