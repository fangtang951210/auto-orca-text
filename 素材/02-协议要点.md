# Orca 编排协议要点(译自官方 orchestration skill,关键条款)

来源:`orca skills get orchestration`(装机自带,门禁要求的必读物)

## 角色路由(先认清自己是谁)

| 你的处境 | 角色 | 该走的路 |
|---|---|---|
| 要监督/等结果/协调多工/决策门 | 协调者 | 走监督循环(七步流程) |
| 收到系统注入的 preamble(含 Task/Dispatch ID) | 工人 | 按 preamble 干活,完成发 worker_done |
| 只想把活丢给另一个 agent,不监督 | 交接 | 用 orca-cli(worktree create --agent / agent launch),**不建 Run、不监控完成**(这条路线"失联"是设计行为,不是 bug) |
| 无 preamble 也无监督要求 | 普通终端 agent | 不发任何生命周期消息 |

关键条款:`--model`/`--effort` 参数**不构成监督**;要监督只有 worker-start 一个入口。

## 权威与安全底线
- Run = 账本(不调度任何人);Task = 工作;Dispatch = 一次权威尝试
- 生命周期权威只来自**活跃的 Dispatch**,工人必须使用 preamble 注入的精确参数,**禁止自造/改写/扩展**(`--from worker` 这种自造身份会被系统拒收,真实案例见踩坑实录)
- `worker-start` 非零退出**不要重启**,读 receipt 的 failedStage,按 references/recovery-and-cleanup.md 处理
- `dispatch --inject` 是逃生舱(留下不受监督的进程),不是主路

## 工人义务(preamble 注入,五条)
1. 只做当前 Task;要问协调者用 preamble 里的 ask 命令(阻塞式),不开本地问答
2. 心跳按节奏发;心跳只证明活着,不证明完成
3. 每个自然检查点读协调者来信(check --terminal),逐条 ack,未 ack 的信会重放并**遮住新信**
4. worker_done **只发一次**,从被派工的终端发出,带三句执行摘要+两个生命周期 ID+明确的 --outcome succeeded/failed(失败不许只用文字带过)
5. 发完 worker_done 就闲置等下一步,不要轮询或自己开工

## 任务卡五要素契约
每张 spec 必须自包含:Target(目标文件)/ Change(具体产出)/ Constraints(不许碰什么)/ Ownership(归谁改)/ Observable acceptance(什么证据算完成)。

## 完成核算(协调者)
- 有效的 worker_done 自动结算 Task 和 Dispatch,**不要**再跟 task-update --status completed
- 每个结算的终端必须三选一:复用该终端派新活 / worker-retain 保留 / worker-release 释放
- 连续三次空等 → 停止盲等,worker-list 枚举,按每行 nextAction 的字面 argv 行动;"没有消息"永远不构成停止/重试/释放的依据

## 放置参考要点(placement)
- 新工人 = 新终端,默认用 current 或指定已有工作区;**建 worktree 仅当用户要求或真实文件冲突**
- folder 项目不能 new-child;围挡两步法(先 worktree create 再 worker-start --worktree id:完整id)
