# 已验证命令序列(全部于 2026-10-28 实测通过)

约定:`ORCA = /Applications/Orca.app/Contents/Resources/bin/orca`(下文直接写 orca,实际调用用完整路径或先 alias)

## A. 七步标准流程(快速通道,工人直接在当前工作区干活)

```bash
# ① 确认 runtime 就绪(app/runtime 都要 ready)
orca status --json
# 实测输出要点: runtime.state="ready", runtime.reachable=true

# ② 建编排 Run(账本),协调者=发起命令的终端,返回 coordinator_handle
cd <你的仓库目录>
orca orchestration run-create --objective "<目标一句话>" --json
# 实测输出: {"run":{"id":"run_xxx","objective":"...","coordinator_handle":"term_xxx",...}}

# ③ 派工人(任务卡五要素:Target/Change/Constraints/Ownership/Observable acceptance)
orca orchestration worker-start --spec '<五要素任务卡>' --worktree current --agent claude --json
# 实测输出: {"taskId":"task_xxx","dispatchId":"ctx_xxx"}
# 启动后必须验证工人真的活了: orca terminal list 里出现新终端

# ④ 心跳处理(工人会发 type=heartbeat 的消息报平安;心跳≠完成)
orca orchestration check --run <run_id> --json
# 返回 deliveryId + messages;按 FIFO 逐条 ack:
orca orchestration check --run <run_id> --ack <deliveryId> --json

# ⑤ 阻塞等待完工回执(官方等待姿势,不要自己写轮询!)
orca orchestration check --run <run_id> --ack <deliveryId> --wait --types "worker_done,escalation,question" --timeout-ms 540000 --json
# 信箱无待签收信(count=0/deliveryId=null)时省略 --ack,直接:
orca orchestration check --run <run_id> --wait --types "worker_done,escalation,question" --timeout-ms 540000 --json
# 收到 type=worker_done,payload 含 outcome/filesModified/taskId/dispatchId

# ⑥ 证据验收(不听摘要,查世界):git log/diff/status + worker-show
git -C <工作区> log --oneline -3 && git show --stat <新提交>
orca orchestration worker-show --dispatch <dispatchId> --json
# 状态应为 state:"succeeded", nextAction.kind:"release"

# ⑦ 结算:ack 回执 + 释放工人
orca orchestration check --run <run_id> --ack <回执的deliveryId> --json
orca orchestration worker-release --dispatch <dispatchId> --json
# 实测:工人终端可能以 "user_takeover" retained 留在界面(可回看操作记录)
```

## B. 隔离通道两步法(工人带自己的 worktree + 分支干活)

背景:folder 型项目(playbook-demo 就曾是)执行 `worker-start --worktree new-child` 会报错
`Folder projects cannot create orchestration worktrees` ——正确姿势两步:

```bash
# 第一步:先建围挡(真 git worktree,自动建分支,名字自动避让重名)
cd <仓库目录>
orca worktree create --repo name:<仓库名> --name <围挡名> --json
# 实测输出: id: <repoId>::<围挡完整路径>, branch: refs/heads/<git用户名>/<围挡名>(带 git 用户名前缀, 非裸围挡名, 以实际返回为准) <!-- issue#14/15/18 -->

# 第二步:工人派进围挡(注意 selector 必须用完整 id,格式 id:<repoId>::<path>)
orca orchestration worker-start --spec '<五要素任务卡>' \
  --worktree "id:<repoId>::<围挡完整路径>" --agent claude --json
```

## C. 分支成果走 GitHub(接 PR 流程)

```bash
cd <围挡路径>
# 注意: <分支名>不是裸围挡名, 带 <git用户名>/ 前缀; 先 git branch --show-current 查实际分支名 <!-- issue#14/15/18 -->
git push -u origin <分支名>
gh pr create --base main --head <分支名> --title "..." --body "..."
# 人审或 gh pr merge <PR号> --merge --delete-branch
```

## D. 清理(恢复初始)

```bash
orca orchestration reset --all                       # ⚠️ 全局重置: 清本机所有 run 的账(含其他会话/项目) <!-- issue#14/15/18 --> <!-- issue#23/24 -->
# reset --tasks 实测执行成功且不清 run 账本本身(run-list 不变); --tasks/--messages 是按数据类型(任务/消息)选择清理范围而非按 run; 精确作用范围未完全确证, 用前以 orca orchestration reset --help 实时输出为准 <!-- issue#23/24 -->
orca terminal close --worktree name:<围挡名> --all    # 关围挡下全部终端
orca worktree rm --worktree name:<围挡名> --force     # 删围挡(注意:不删分支! 返回 ok ≠ 删完, 目录是异步删除) <!-- issue#23/24 -->
sleep 2                                              # 实测: rm 返回 ok 后目录仍在异步删除中, 立即删分支会报 cannot delete branch used by worktree <!-- issue#23/24 -->
cd <仓库> && git worktree prune && git branch -D <实际分支名>   # 实测顺序: rm → sleep 2 → prune → 删分支; 立即删会报 cannot delete branch used by worktree; <实际分支名>带 <git用户名>/ 前缀, 先 git branch --show-current 查 <!-- issue#14/15/18 --> <!-- issue#23/24 -->
git fetch --prune                                    # 清远程引用缓存
# 补充: repo add 的注册目前无 CLI 注销(实测无 repo rm), 留在 Orca 里无害, 要移除走 App 界面 <!-- issue#14/15/18 -->
```

## E. 诊断命令(出问题时按官方路径查,不要瞎猜)

```bash
orca orchestration worker-show --dispatch <dispatchId> --json
# 看: state(succeeded/failed) / liveness.verdict(live/unverifiable/exited) /
#     nextAction.kind + nextAction.argv(官方把下一步命令都算好了)
orca orchestration worker-list --run <run_id> --include-remote --json
orca terminal read --terminal <handle> --screen   # 看终端当前画面(注意:是快照不是实时)
```
